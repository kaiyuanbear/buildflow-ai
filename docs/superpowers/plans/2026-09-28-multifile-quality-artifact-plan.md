# 多文件高质量应用产物实施计划

## 里程碑 1：契约与兼容层

1. 扩展共享 `GeneratedApplication` 契约，增加 `manifest` 和受限嵌套路径；保留旧版四文件产物的可选 manifest 兼容分支。
2. 定义路径、语言、文件数量、单文件/总字节数的白名单常量，并将其作为 API 与 Web 的唯一来源。
3. 为蓝图增加 `complexityTarget`，定义区域、交互、数据和响应式的最低值。
4. 更新数据库 JSON 类型与 workspace API 类型；不做破坏性迁移。

**完成标准：** 新旧产物均能由 Zod 解析；非法路径、重复文件和不完整 manifest 被拒绝。

## 里程碑 2：安全预览组装

1. 抽出纯函数，根据 manifest 将 CSS 与 JS 按顺序安全内联到 `iframe.srcDoc`。
2. 对 HTML 中的外部 `link`、`script src`、CSS `url()` 与 JS `import` 继续拒绝。
3. 保留现有 CSP、`sandbox="allow-scripts"` 和 preview-state bridge。
4. 对历史四文件版本使用旧的 `styles.css`、`app.js` 默认顺序。

**完成标准：** 多文件与历史版本都可加载；不允许的网络/父窗口/存储能力无法进入预览。

## 里程碑 3：生成提示词与质量门槛

1. 修改蓝图提示词，要求依据用户需求提出复杂度目标，而非选择固定应用模板。
2. 修改产物提示词，要求 7–12 个文件、manifest、职责拆分、演示数据和受控状态桥接。
3. 把主产物与修复预算调整为 18K tokens、100 秒单次时限、300 秒总时限。
4. 实现确定性质检，返回可读的缺口列表：区域、交互、初始数据、状态反馈、窄屏布局、文件组织。
5. 安全校验或质量校验失败时，只发起一次完整替换修复；否则使用本地起步应用。

**完成标准：** 生成日志能区分结构安全问题与质量不足；不能因增加复杂度而绕过安全白名单。

## 里程碑 4：Builder 文件树与中文事件

1. 将中栏文件列表替换为路径树；保留文件选择、高亮和源码查看。
2. 补充并统一中文事件：复杂度规划、生成多文件产物、结构安全校验、质量校验、质量修复、逐文件保存、预览就绪。
3. 为旧事件与旧版本提供中文显示默认值，避免历史项目显示异常。
4. 校验桌面三栏滚动与窄屏单栏下的文件树可读性。

**完成标准：** 用户能看出哪些文件属于 `styles/` 和 `src/`，并能理解每个真实生成步骤。

## 里程碑 5：测试、基准与交付

1. 新增 API 单元/集成测试：多文件成功、manifest 不匹配、质量不足后修复、修复后仍失败、旧四文件兼容、所有权和活动任务限制。
2. 新增浏览器测试：中文时间线、路径树展开、预览交互与刷新持久化、再生成与恢复版本。
3. 用三类非模板提示词进行 DeepSeek 基准生成，记录文件数、质量门槛、时长、是否修复与最终状态。
4. 执行 `pnpm typecheck`、`pnpm build`、API QA、Playwright 与公开 Render 冒烟测试。
5. 更新 README、QA checklist、decision log 与面试演示脚本；仅在所有检查通过后推送并触发 Render 部署。

**完成标准：** 三类提示词均有可演示的非降级样例或有明确的、真实记录的降级原因；交付文档说明当前边界。

## 实施顺序与回滚

先完成里程碑 1 和 2，再更改模型输出与质量门槛，最后改变 Builder 呈现。这样任一步失败都能回退到已保存的旧四文件预览；不修改历史版本的数据，也不迁移或删除现有项目。
