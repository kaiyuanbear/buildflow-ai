# 增量版本保真设计

## 背景与目标

BuildFlow AI 的版本链路应符合用户的自然预期：首次提示词生成 `V1`；后续优化提示词在未明确要求重构时，生成 `Vn+1` 必须保留 `Vn` 的产品目的、现有页面内容、交互和文件结构，并在此基础上增加或局部修改内容。

例如“新增 2 个 Tab 页面：英雄介绍和新手教程，设计风格统一”属于扩展，而不是允许重写首页。成功标准是：原首页及原有功能仍可使用；新增导航项能进入有实际内容的页面；刷新和本地交互状态仍然可靠；模型或校验失败时回退到可运行的上一版本。

本设计仅覆盖生成产物与其版本连续性，不改变登录、项目权限、数据库、iframe 隔离边界或 AI 密钥管理。

## 约束与原则

- 生成代码继续只在 sandboxed iframe 中运行，服务端绝不执行生成代码。
- 默认不向 DeepSeek 发送上一版本的完整源码或预览状态；已有的能力摘要继续是无源码、无用户数据的参考信息。
- 所有可见产物、Agent 流程和默认生成内容为简体中文，除非用户明确要求其他语言。
- 连续性校验保护未被明确授权变更的部分；明确要求“重构、替换、删除、重新设计”时，允许在对应维度调整，而不是无条件禁止修改。
- 生成候选不满足安全、质量或连续性校验时，不保存为新版本；增量流程回退为上一版本的完整、可交互产物。

## 方案比较与选择

### 方案 A：仅增加提示词约束

在提示词中要求“保留原有内容”。改动最少，但模型仍只看到摘要，无法准确复原既有结构；也无法以确定性规则阻止整页重写。该方案不能满足“同一项目增量版本保留原有功能”的评估重点。

### 方案 B：默认严格增量语义与校验（采用）

蓝图阶段将优化意图解析为细粒度变更范围；生成阶段要求保留所有未授权的文件、锚点、组件、事件绑定和页面区域；服务端以确定性规则拒绝破坏性候选。它不需要新增外传数据，适合作为所有用户的默认体验。

局限是：只发送摘要时，系统能验证结构性保留，不能对任意 HTML/CSS 的每一处视觉文本做绝对逐字保真。因此它会显著降低误重写，但不承诺像源码补丁那样的逐字符保持。

### 方案 C：经逐次授权的源码感知补丁（第二层，可选）

当用户在某次增量生成前主动勾选授权时，API 才将该项目当前版本的“已生成浏览器产物源码”发给 DeepSeek，并要求在此基础上做最小变更。此模式能给模型完整上下文，最接近精确增量更新。

它必须是默认关闭、每次操作独立确认的能力。传输范围只含当前版本 `index.html`、`styles/*`、`src/*`、生成 README 和结构清单；不含平台前后端源码、密钥、Cookie、登录信息、数据库数据或预览持久化状态。API 不记录该源码到日志或 Agent 时间线。用户未勾选时绝不传输。

本次实施以方案 B 为默认主路径，同时建立方案 C 的数据接口、授权 UI 和审计字段；实际传输只有在用户主动确认时启用。

## 细粒度变更范围

现有三个布尔字段不足以描述“新增”。将其替换为如下蓝图与版本元数据：

```ts
type IncrementalChangeScope = {
  productPurpose: "preserve" | "change";
  fileStructure: "preserve" | "change";
  interactions: "preserve" | "additive" | "modify" | "replace";
  pageContent: "preserve" | "extend" | "replace";
  visualStructure: "preserve" | "extend" | "rebuild";
};
```

蓝图提示词将明确以下默认判定：

| 用户措辞 | 解析结果 |
| --- | --- |
| 新增、增加、补充、扩展、再加一个 | `interactions: additive`、`pageContent: extend`、`visualStructure: extend`；其他为 `preserve` |
| 调整某个表单、修改某个按钮行为 | `interactions: modify`；未涉及的维度为 `preserve` |
| 替换、删除、重构、重新设计、改成另一类产品 | 对应维度允许 `change`、`replace` 或 `rebuild` |
| 仅优化文案、颜色、间距 | `pageContent: extend` 或局部 `visualStructure: extend`，不得放宽功能与文件结构 |

旧版本中保存的布尔值在读取时兼容映射：`false → preserve`；旧 `interactions: true → modify`；旧 `productPurpose/fileStructure: true → change`。新版本一律写入完整的新对象。

## 默认增量生成流程（方案 B）

1. 用户提交优化提示词。API 读取当前版本及其生成文件，建立不可变基线快照。
2. DeepSeek 蓝图仅接收原始需求、优化需求和无源码能力摘要，输出细粒度 `changeScope`、新增项和验收目标。
3. API 显示中文“变更范围”事件，例如“保留首页、既有交互与文件结构；新增英雄介绍和新手教程页面”。
4. DeepSeek 生成完整的候选产物；产物必须包含本次新增或修改的 `changeManifest`：`preserved`、`added`、`modified` 三组组件/页面标识。
5. 服务端先执行安全与质量校验，再执行连续性校验。只有全部通过时，才保存为新版本并设为当前版本。
6. 若首次候选失败，服务端只请求一次带有具体失败原因的受限修复。修复仍失败时，保存上一版本的完整产物作为安全回退，并在 Agent 时间线明确标注“未生成新版本内容，已保留 Vn”。

### 基线快照与连续性校验

基线从 `Vn` 的文件中计算并在本次请求内使用，不依赖浏览器端状态。默认保护的项目为：

- 全部既有文件路径、样式/脚本运行顺序及交互模块；
- 所有带 `id` 的稳定组件、内部锚点目标和既有语义区域；
- 既有 `addEventListener` 绑定及交互数量；
- 已声明的导航/Tab 对应内容区域与初始演示数据；
- `Vn` 已通过校验的预览入口和状态保存桥接调用。

当范围为 `preserve` 时，候选必须是基线的超集；当范围为 `additive/extend` 时，新增项必须出现在 `changeManifest.added` 中，且具备非空内容、可到达入口和至少一个有意义交互。对于 Tab，校验要求导航项、目标 `role=tabpanel`/目标 ID、可见标题和内容同时存在；不能只增加空白链接。

当范围显式为 `modify`、`replace` 或 `rebuild` 时，仅解除相应维度的保护，其他维度继续按基线校验。所有范围都继续受安全、预览运行时、中文可见文案和质量门槛约束。

## 可选源码感知模式（方案 C）

### 用户体验与授权

- 优化输入框下增加默认未选中的复选框：`允许将当前版本的已生成前端源码发送给 DeepSeek，以便基于原版进行更精确的增量修改。`
- 复选框旁说明传输范围与不传输内容；用户不勾选时仍可使用默认方案 B。
- 授权只对本次生成有效，下一次重新默认关闭。时间线与版本元数据记录 `sourcePatchConsent: true/false`，不记录源码。
- 新建项目不显示此项；只有存在当前版本的优化生成才可选。

### API 与模型边界

- 优化接口接受 `sourcePatchConsent?: boolean`，仅在项目归属校验通过、确为增量生成且值为 `true` 时组装源码上下文。
- 源码上下文由服务端从当前版本读取，禁止浏览器上传任意文件；从而避免用户注入平台源码或机密内容。
- 模型指令要求“最小变更、保留未授权区域、输出完整符合契约的产物和 changeManifest”。完整产物仍需通过与方案 B 相同的全部验证。
- API 日志只记录是否启用该模式、文件数量和校验结果；不得记录 prompt 之外的源码正文或模型原始响应正文。

源码感知模式提高保真度，但并不跳过验证，也不保证模型会完全遵守指令；连续性规则仍是最终准入门槛。

## 前后端组件与数据流

### Contracts

- 细粒度 `incrementalChangeScopeSchema` 与 `changeManifestSchema`。
- `StoredAppSpec.generationRequest` 新增 `sourcePatchConsent` 与完整 `changeScope`；JSON 元数据不需要数据库迁移。
- 生成请求 schema 新增可选的 `sourcePatchConsent`，仅允许布尔值。

### API

- `generation.ts` 拆分为：范围解释、基线提取、模型上下文构建、候选验证、回退处理五个明确职责。
- 范围解释器统一将旧布尔字段归一化，生成中文的用户可见描述。
- 增量验证器按每个维度决定保护规则，并对新增导航/Tab/详情页检查“入口—目标—内容—交互”的完整链路。
- 回退不创建伪造的“更新成功”内容：版本摘要和 Agent 事件明确标记为已保留上一版本。

### Web

- 优化输入增加本次授权开关和简短隐私说明；请求成功后立即复位。
- Agent 时间线展示 `Vn` 提示词后跟随该次蓝图、变更范围、生成、校验、保存事件，避免不同版本提示词聚集在顶部。
- 版本详情展示中文变更摘要：保留项、新增项、经授权修改项和是否采用源码感知模式。

## 错误处理与回退

- 蓝图 JSON、候选 JSON、契约、安全、质量、连续性或 iframe 运行时检查任一失败，都生成可定位的中文失败原因。
- 首次失败可以进行一次受限修复；不会无限重试或扩大模型权限。
- 增量失败时，预览使用 `Vn` 原产物，包含其原有的事件绑定与持久化桥接；数据库当前版本不指向不合格候选。
- 前端把“回退保留”标为警告而不是“构建完成”，使面试评审能辨别真实结果。

## 测试与验收

### API / 单元与契约测试

- “新增两个 Tab”解析为 `additive + extend`，不是 `replace/rebuild`。
- 未明确要求修改的文件、ID、事件、锚点、区域和交互数被删除时，候选被拒绝。
- 显式“重构导航”仅放宽视觉/交互相关保护，不放宽产品目的或文件结构。
- 新增 Tab 缺少对应内容面板、目标 ID 或演示内容时，候选被拒绝。
- 无 AI、模型异常和校验失败时，增量回退完整复用 `Vn` 文件。
- `sourcePatchConsent=false/缺省` 时模型上下文不含任何文件正文；为 `true` 时只含允许范围的当前生成产物，日志不含正文。

### Playwright 端到端测试

- 生成 V1 后以“新增两个 Tab”生成 V2，验证 V1 首页核心区域及交互仍存在；两个新增 Tab 能显示非空页面并可交互。
- 切换 Tab、勾选控件和关闭弹框后，iframe 不重载、不回到顶部；刷新后状态恢复。
- 强制无效候选时，界面显示中文回退提示，预览仍是 V1 且可交互。
- 勾选源码感知授权后，时间线和版本信息能显示已授权；不勾选时不显示已授权。

QA 证据继续记录在 `docs/qa-checklist.md`；任何产品或安全边界改变记录在 `docs/decision-log.md`。

## 非目标

- 不执行生成代码、不允许生成代码访问网络、存储、父窗口或平台 Cookie。
- 不把应用变成固定模板库，也不为某个行业硬编码页面。
- 不对任意第三方模型输出承诺像素级一致性；默认模式提供结构和行为的强连续性，源码感知模式用于提高内容保真度。
- 不在本次变更中增加多人协作、云端发布、支付或模型选择功能。
